# 量化交易使用说明（OKX 永续合约）

把 PA Agent 的第二阶段决策（限价单 / 突破单 / 市价单 + 止损 + 两段止盈）自动下到 **OKX 永续合约**，并在网页面板里查看收益、交易明细和 AI 质量分析。

> ⚠️ 默认是 **模拟盘**。AI 的分析不构成投资建议；在模拟盘验证出稳定正收益之前，不要切换实盘。

---

## 1. 架构

```
桌面程序（持续跟踪分析）  ─┐
                          ├─ 每次分析写一条「信号」 ─▶ trade_records/quant.db (SQLite)
后台分析 pa_agent.headless ─┘                                 │
                                                             ▼
                                交易服务 pa_agent.trading（执行器，每 3 秒一轮）
                                  风控 → OKX 下单 → 成交/止损/止盈 → 平仓结算
                                                             │
                                                             ▼
                                        收益面板 http://127.0.0.1:8765
```

- **数据源**：数据来源选 **OKX**（品种如 `BTC-USDT-SWAP`），分析用的 K 线和实际交易的合约是同一份价格。用 TradingView 的 `BTCUSDT` 也能交易（会映射到 `BTC-USDT-SWAP`），但两边价格有细微差别。
- **执行器和分析是两个独立的部分**：分析进程崩了，交易所上已有的止损 / 止盈照常有效；交易服务停了，挂单和止损也留在交易所上，下次启动会接着管理。

## 2. 快速开始（模拟盘）

### 2.1 创建 OKX 模拟盘 API Key

1. 登录 OKX → 切换到 **模拟交易**（Demo Trading）。
2. 个人中心 → **模拟交易 API** → 创建 API Key，权限勾选 **读取 + 交易**（不要勾提币），记下 API Key、Secret Key 和你设置的 Passphrase。
3. 模拟账户的 **账户模式** 要是「单币种保证金」或以上，「简单模式」不能交易合约。

> 模拟盘必须用模拟交易里创建的 Key，实盘 Key 在模拟盘会报 `50119` / `50101`。

### 2.2 配置

编辑 `config/settings.json` 的 `trading` 段（字段说明见第 4 节；没有这一段时，程序首次保存设置会自动生成默认值，也可以参考 `config/settings.example.json`）：

```json
"trading": {
  "enabled": true,
  "demo": true,
  "okx_api_key": "…",
  "okx_secret_key": "…",
  "okx_passphrase": "…",
  "leverage": 5,
  "risk_per_trade_pct": 1.0
}
```

也可以不把密钥写进文件，用环境变量 `OKX_API_KEY` / `OKX_SECRET_KEY` / `OKX_PASSPHRASE`（优先于文件）。

### 2.3 检查

```bash
make trade-check        # 或 uv run python -m pa_agent.trading check
```

能看到「账户权益 …」和「持仓模式 …」就说明连通了。国内网络访问 OKX 需要代理：

```bash
export https_proxy=http://127.0.0.1:7897 http_proxy=http://127.0.0.1:7897 no_proxy=localhost,127.0.0.1
```

### 2.4 运行（二选一）

**方式 A：桌面程序 + 交易服务**（本机，边看边跑）

```bash
make trade-run          # 终端 1：交易执行器 + 收益面板
make uv-run             # 终端 2：桌面程序，数据来源选 OKX，勾「持续跟踪分析」
```

**方式 B：无窗口后台（VPS 推荐）**——分析、执行、面板都在一个进程里：

```bash
make headless SYMBOLS=BTC-USDT-SWAP,ETH-USDT-SWAP TF=1h
# 等价于
uv run python -m pa_agent.headless --symbols BTC-USDT-SWAP,ETH-USDT-SWAP --timeframe 1h --trade
```

常用参数：`--now`（启动后立刻分析一次，不等收盘）、`--once`（只分析一次就退出，用来试跑）、`--source tradingview`、`--bars 150`、`--no-dashboard`。不加 `--trade` 就只做分析、记录和飞书推送，不下单。

打开 **http://127.0.0.1:8765** 查看面板。

## 3. 交易规则

### 3.1 AI 决策 → OKX 订单

| AI 输出 | OKX 下法 |
|---|---|
| 市价单 | 市价开仓，同时附带止损 |
| 限价单 | 限价开仓，同时附带止损；如果限价已经优于现价（会立刻成交），按市价处理 |
| 突破单 | `breakout_mode=trigger`：OKX 条件单，触发后市价开仓并附带止损；`watch`：执行器自己盯价格，突破后下市价单。分析期间价格已经越过突破价，直接按市价入场 |

成交后：止盈1 挂 `tp1_close_fraction`（默认 50%）仓位的只减仓限价单，止盈2 挂剩余仓位；止盈1 成交后，剩余仓位的止损移到开仓均价（保本）。AI 没给止盈2 或拆仓后数量低于最小下单量时，全部在止盈1 离场。

### 3.2 订单生命周期

- **一个品种同时只有一笔交易**，不加仓、不反手；已有持仓时新信号会被跳过，持仓只通过止损 / 止盈离场。
- **最新分析覆盖挂单**：新信号方案不同 → 撤掉旧挂单换新单；方案相同（价格差在一跳以内）→ 保留；新分析结论是「不下单」或新信号没通过风控 → 撤掉挂单。
- **挂单过期**：限价 / 突破单 `pending_expiry_bars`（默认 3）根 K 线内没成交就撤销；撤单时如果已经部分成交，按成交部分转为持仓管理。只有交易所确认撤单成功后才算撤销，没确认就下一轮继续撤，在此期间不会再开新仓。
- **部分成交也有止损**：OKX 要等入场单全部成交才会生效附带的止损，所以限价单部分成交时，执行器会先给已成交部分单独挂止损。
- **止损每轮对账**：只要有持仓，执行器每轮（默认 3 秒）都会核对这个品种在交易所上的止损单，只保留一张数量等于当前仓位、价格正确的止损，多余或过期的撤掉，缺了就补（止盈1 成交后止损自动缩到剩余仓位）。补不上就立即市价平仓，不让仓位裸奔。
- **不明确的下单结果按订单号核实**：下单请求超时等情况下，不会直接当作失败，而是按客户端订单号去交易所查实际状态，避免留下无人管理的订单，也不会重复下单。

### 3.3 风控（写在代码里，不交给 AI）

下单前逐条检查，任何一条不满足就拒绝，原因记在面板的「信号记录」里：

- 有止损、有止盈，止损在入场价的亏损方向、止盈在盈利方向；
- 现价还没越过止损；
- 止损距离在 `min_stop_distance_pct` ~ `max_stop_distance_pct` 之间；
- 盈亏比（止盈1）≥ `min_reward_risk`；
- AI 交易把握度 ≥ `min_trade_confidence`（0 = 不限制）；
- 同时持仓 / 挂单数 < `max_open_positions`；
- 今日已实现亏损没超过 `max_daily_loss_pct`（超过后当天不再开新仓）。

**仓位计算**：张数 = 账户权益 × `risk_per_trade_pct`% ÷ (|入场 − 止损| × 每张合约币数)，再受 `leverage` 倍杠杆和可用保证金限制，按最小下单单位向下取整。例如 1 万 U 权益、单笔风险 1%，打到止损亏约 100 U（不含滑点和手续费）。

### 3.4 紧急停止

面板右上角「紧急停止」或 `make trade-kill`：撤销所有挂单、市价平掉所有由系统管理的仓位，并拒绝新信号，直到「解除紧急停止」（`make trade-resume`）。

## 4. 配置字段（`settings.json → trading`）

| 字段 | 默认 | 说明 |
|---|---|---|
| `enabled` | `false` | 总开关：关闭时分析结果不生成交易信号 |
| `demo` | `true` | `true` 模拟盘；`false` 实盘（启动还需加 `--i-understand-live`） |
| `okx_api_key` / `okx_secret_key` / `okx_passphrase` | 空 | 也可用环境变量 `OKX_*` |
| `margin_mode` | `isolated` | 逐仓 `isolated` / 全仓 `cross` |
| `leverage` | `5` | 杠杆倍数，同时是仓位名义价值上限（权益 × 杠杆） |
| `risk_per_trade_pct` | `1.0` | 单笔风险占权益的百分比 |
| `max_daily_loss_pct` | `3.0` | 单日亏损熔断 |
| `max_open_positions` | `1` | 最多同时持仓 / 挂单的品种数 |
| `min_reward_risk` | `1.0` | 最低盈亏比 |
| `min_trade_confidence` | `0` | AI 交易把握度门槛 |
| `min_stop_distance_pct` / `max_stop_distance_pct` | `0.05` / `8.0` | 止损距离范围（% of 入场价） |
| `pending_expiry_bars` | `3` | 挂单过期根数 |
| `tp1_close_fraction` | `0.5` | 止盈1 平掉的比例 |
| `move_stop_to_breakeven` | `true` | 止盈1 后移保本止损 |
| `breakout_mode` | `trigger` | 突破单用 OKX 条件单（`trigger`）还是本地盯盘（`watch`） |
| `poll_interval_s` | `3.0` | 执行器轮询间隔 |
| `dashboard_host` / `dashboard_port` | `127.0.0.1` / `8765` | 面板监听地址 |
| `dashboard_token` | 空 | 面板访问令牌；监听非本机地址时必填，访问时用 `http://host:8765/?token=…` |

## 5. 面板与命令

面板内容：账户权益曲线、净盈亏、胜率、盈亏比、利润因子、平均 R、最大回撤、手续费和资金费；当前持仓 / 挂单；交易明细（点开可看当时 AI 的完整分析、K 线截图和执行记录）；AI 质量分析；信号记录；系统事件。

| 命令 | 作用 |
|---|---|
| `make trade-check` | 检查行情、密钥、账户模式 |
| `make trade-run` | 交易执行器 + 面板 |
| `make headless` | 后台分析 + 执行器 + 面板 |
| `make trade-report` | 命令行版收益和 AI 质量报告（`--days 7` 只看近 7 天） |
| `uv run python -m pa_agent.trading status` | 活跃交易和最近事件 |
| `make trade-kill` / `make trade-resume` | 紧急停止 / 解除 |

日志：`logs/trading.log`（交易服务单独运行时）、`logs/pa_agent.log`（后台分析和桌面程序）。

## 6. 模拟盘评估（阶段 4）

这一步只能靠时间：**至少跑 2~4 周、累计 30 笔以上平仓**再下结论，样本太少的胜率没有意义。每周看一次面板或 `make trade-report`：

1. **扣掉手续费和资金费后净盈亏 > 0**，利润因子 > 1.2，平均 R > 0。不满足就不该切实盘。
2. **最大回撤**在你能接受的范围内（例如 < 10%）。
3. **AI 把握度是否有区分度**：「按交易把握度」分组里，把握度越高实际胜率应该越高。如果高把握度组明显更好，把 `min_trade_confidence` 设到那个分组的下限；如果各组差不多，说明把握度没参考价值，不要靠它过滤。
4. **AI 估计胜率 vs 实际胜率**：长期偏高说明 AI 过度自信。
5. **按入场方式 / 市场周期 / 离场原因**：找出明显亏钱的组合（比如突破单、或某种周期），考虑在提示词或风控里排除。
6. **信号漏斗**：风控拒绝太多，看拒绝原因是止损太近、盈亏比不够还是别的，再调对应参数。

> 模拟盘成交比实盘理想（滑点小、流动性好），模拟盘的结果要打折看。

## 7. VPS 部署

海外 VPS 可以直连 OKX 和 DeepSeek，不需要代理。

### Windows Server（推荐）

1. 安装 Git、Python 3.11、uv（`pip install uv`）。
2. `git clone https://github.com/Lzhtommy/PA_Agent.git`，进入目录，复制 `config/settings.example.json` 为 `config/settings.json` 并填写 AI Key 和 `trading` 段（或先运行一次桌面程序在界面里填 AI Key）。
3. `uv sync --extra trading`，然后 `uv run python -m pa_agent.trading check`。
4. 运行 `uv run python -m pa_agent.headless --symbols BTC-USDT-SWAP --timeframe 1h --trade`。
5. 开机自启：「任务计划程序」新建任务，触发器「启动时」，操作运行上面的命令（起始于项目目录），勾选「不管用户是否登录都要运行」。

### Linux（Ubuntu）

后台程序不需要桌面，但分析模块用到了 PyQt6 的 QtCore（信号机制），需要装 Qt 的基础库；截图里的中文需要中文字体：

```bash
sudo apt install -y git libglib2.0-0 libegl1 libgl1 libxkbcommon0 libdbus-1-3 fonts-noto-cjk
curl -LsSf https://astral.sh/uv/install.sh | sh
git clone https://github.com/Lzhtommy/PA_Agent.git && cd PA_Agent
uv sync --extra trading
uv run python -m pa_agent.trading check
```

systemd 服务（`/etc/systemd/system/pa-agent.service`）：

```ini
[Unit]
Description=PA Agent headless trading
After=network-online.target

[Service]
WorkingDirectory=/home/ubuntu/PA_Agent
ExecStart=/home/ubuntu/.local/bin/uv run python -m pa_agent.headless --symbols BTC-USDT-SWAP --timeframe 1h --trade
Restart=always
RestartSec=10
Environment=QT_QPA_PLATFORM=offscreen

[Install]
WantedBy=multi-user.target
```

`sudo systemctl enable --now pa-agent`，日志 `journalctl -u pa-agent -f`。

### 远程看面板

面板默认只监听 `127.0.0.1`。推荐用 SSH 隧道，不对公网开放端口：

```bash
ssh -L 8765:127.0.0.1:8765 user@your-vps   # 然后本机浏览器打开 http://127.0.0.1:8765
```

一定要对外开放时，设置 `dashboard_host: "0.0.0.0"` 和一个足够长的 `dashboard_token`，并在防火墙里只放行自己的 IP。OKX API Key 建议绑定 VPS 的 IP 白名单。

## 8. 切换实盘

1. 在 OKX 实盘创建 API Key（读取 + 交易，绑定 IP 白名单，**不要开提币**），确认账户模式不是简单模式。
2. 先用小资金、较低的 `risk_per_trade_pct`（如 0.25~0.5）和 `leverage`。
3. `settings.json` 里 `"demo": false`，换上实盘 Key。
4. 启动命令加 `--i-understand-live`，否则程序会拒绝以实盘模式启动。面板左上角会显示红色「实盘」。

## 9. 已知限制

- **突破单的 OKX 条件单附带止损** 还没在模拟盘实测过；如果 OKX 拒绝这种下法，信号会记为「错误」，可以把 `breakout_mode` 改成 `watch`（执行器本地盯盘）。成交后执行器还会检查止损是否存在，没有就补下。
- 只支持 OKX USDT 永续合约、单向持仓模式（net_mode）；首次运行会尝试把账户切换为单向持仓（有持仓时 OKX 不允许切换）。
- 平仓盈亏取自 OKX 的「历史持仓」接口，平仓后可能延迟几秒到两分钟才结算到面板。
- 交易参数暂时只能改 `settings.json`，桌面程序的设置界面里还没有对应页面。
- 同一个品种在交易所上手动开的仓位，执行器不会管理，只会在事件里提醒一次。
- **不要在系统正在交易的品种上手动挂止损单或只减仓单**：执行器开新仓前、平仓后，以及持仓期间对账止损时，会撤掉这个品种上不属于当前交易的条件止损单和只减仓挂单。
